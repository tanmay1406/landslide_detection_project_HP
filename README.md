# Landslide Prediction and Risk Mapping System

## Overview

Landslides are among the most destructive natural hazards in mountainous regions, causing significant loss of life, infrastructure damage, and economic disruption.

This project develops an end-to-end geospatial machine learning pipeline for landslide susceptibility prediction and risk mapping in **Himachal Pradesh, India**. The system integrates terrain, infrastructure, hydrological, vegetation, and climate-related features derived from multiple geospatial datasets and evaluates machine learning models for regional-scale landslide risk assessment.

The project includes:

- DEM-based terrain feature extraction
- OpenStreetMap infrastructure and land-use analysis
- NDVI vegetation analysis
- NASA POWER rainfall integration
- Machine learning model training and evaluation
- Landslide susceptibility classification and risk mapping

---

## Study Area

**Himachal Pradesh, India**

High-resolution geospatial datasets covering the state were processed to construct a large-scale landslide susceptibility dataset containing approximately **56,000 samples**.

### 06_bagging_boosting_models.ipynb

Broadens the two ensemble families that `05_ML_model.ipynb` / `05_ML_model_3.ipynb`
already (implicitly) started: Random Forest is itself a **Bagging** method and XGBoost is
itself a **Boosting** method. This notebook adds more of each, on the same 4-class and
3-class label schemes, so the comparison is paradigm-level rather than two-models-level.

Models added:

- **Bagging family:** Bagging Classifier (bootstrap-aggregated Decision Trees), Extra Trees
- **Boosting family:** AdaBoost, Gradient Boosting, LightGBM, CatBoost

Results (test accuracy / macro F1, both class schemes) are in
[Model Performance Summary](#model-performance-summary) below. Headline finding: the
Bagging family wins on raw accuracy but overfits far more (30-43 point train/test gap)
than the Boosting family (top out lower, but generalize with a 5-14 point gap).

---

### 07_cnn_image_model.ipynb

Adds a CNN -- the hardest of the three additions, since **this repository's shared data
does not include the raw DEM/OSM rasters**, only the already-extracted point CSVs. This
notebook reconstructs genuine 16x16x12 spatial image patches by interpolating each
continuous feature (elevation, slope, roughness, distances, NDVI, rainfall, circularly-safe
aspect) across the study area from the 56,008 labeled points themselves
(`scipy.interpolate.LinearNDInterpolator`), then cutting out a real spatial neighborhood
around each point -- verified to reproduce each point's own tabular feature value exactly
at the patch center.

Results: 58.5% / 47.3% test accuracy (3-/4-class) -- mid-pack accuracy, but the smallest
train/test generalization gap of any model except AdaBoost. See the notebook's own "Key
findings" section for the full read, including the resolution caveat (this is a
regional-scale reconstruction, not the original 30m imagery).

## Dataset Construction Pipeline

### 1. Terrain Feature Engineering

A high-resolution DEM (~13,495 × 12,096 pixels, ~30m spatial resolution) was processed using Rasterio and NumPy to derive:

- Elevation
- Slope
- Aspect
- Terrain Roughness

Generated raster layers:

- `hp_slope.tif`
- `hp_aspect.tif`
- `hp_roughness.tif`

---

### 2. Infrastructure and Land Use Features

OpenStreetMap data was integrated and reprojected to **EPSG:32644**.

Extracted features:

- Distance to nearest road
- Distance to nearest building
- Distance to nearest river
- Building density
- Land-use category

Spatial indexing using **STRtree** was employed to efficiently process tens of thousands of geospatial points.

---

### 3. Vegetation Features

Satellite-derived vegetation information was integrated.

Feature:

- NDVI (Normalized Difference Vegetation Index)

This feature captures vegetation density and land-cover characteristics that influence slope stability.

---

### 4. Climate Features

Daily precipitation data was obtained from NASA POWER datasets.

Extracted features:

- Average 7-day accumulated rainfall
- Average 15-day accumulated rainfall

To improve efficiency, coordinates were grouped into rainfall grid cells before querying the API, reducing thousands of potential requests to fewer than one hundred unique spatial queries.

## Model Performance Summary

Ten distinct models were evaluated across both label schemes -- full methodology in
`06_bagging_boosting_models.ipynb` (Bagging/Boosting broadening), `07_cnn_image_model.ipynb`
(CNN), and `08_final_comparison.ipynb` (the comparison itself). Family = Bagging (bootstrap
aggregation), Boosting (sequential residual fitting), or Deep Learning (MLP on tabular
features, or CNN on reconstructed spatial image patches). "Gap" is train accuracy minus
test accuracy -- lower means less overfitting.

### Four-Class Classification

| Model | Family | Accuracy | Macro F1 | Gap |
|---|---|---:|---:|---:|
| Random Forest | Bagging | **56.96%** | **0.548** | 0.417 |
| Bagging (Decision Tree) | Bagging | 56.95% | 0.538 | 0.431 |
| Extra Trees | Bagging | 55.91% | 0.554 | 0.390 |
| XGBoost | Boosting | 53.78% | 0.489 | 0.144 |
| MLP | Deep Learning (Tabular) | 52.67% | 0.460 | 0.015 |
| LightGBM | Boosting | 50.75% | 0.517 | 0.113 |
| CatBoost | Boosting | 50.09% | 0.512 | 0.070 |
| Gradient Boosting | Boosting | 47.98% | 0.492 | 0.050 |
| CNN (Image Patches) | Deep Learning (CNN) | 47.29% | 0.473 | 0.062 |
| AdaBoost | Boosting | 43.92% | 0.430 | 0.001 |

### Three-Class Classification

| Model | Family | Accuracy | Macro F1 | Gap |
|---|---|---:|---:|---:|
| Random Forest | Bagging | **68.10%** | **0.670** | 0.306 |
| Bagging (Decision Tree) | Bagging | 67.46% | 0.655 | 0.325 |
| Extra Trees | Bagging | 66.70% | 0.663 | 0.282 |
| XGBoost | Boosting | 65.35% | 0.634 | 0.104 |
| LightGBM | Boosting | 62.57% | 0.631 | 0.074 |
| CatBoost | Boosting | 62.31% | 0.629 | 0.051 |
| Gradient Boosting | Boosting | 60.53% | 0.615 | 0.029 |
| CNN (Image Patches) | Deep Learning (CNN) | 58.51% | 0.590 | 0.071 |
| AdaBoost | Boosting | 54.08% | 0.565 | -0.002 |

The best-performing model overall remains the **3-Class Random Forest**, at 68.10% accuracy
/ 0.670 macro F1 -- broadening the Bagging family (Bagging Classifier, Extra Trees) confirmed
it as the strongest option rather than replacing it.

**But raw accuracy isn't the whole picture.** Every Bagging-family model has a 28-43 point
train/test gap (they're memorizing the training set); every Boosting-family model has a
3-14 point gap. XGBoost is the best balance of accuracy and generalization among the
higher-accuracy models: within 2.7-3.2 points of Random Forest's accuracy at roughly a
third of its generalization gap. Gradient Boosting has the smallest gap of any model other
than AdaBoost (2.9-5.0 points) while still clearing 60%/48% accuracy -- on these two axes
together it's arguably the best-balanced model in the project, narrowly ahead of the CNN,
which reaches similarly low overfitting (6.2-7.1 points) from a very different, spatially-
aware architecture. Full discussion, plots, and the accuracy-vs-overfitting trade-off chart
are in `08_final_comparison.ipynb`.

The three-class formulation continues to help **every single model**, not just Random
Forest/XGBoost -- confirming that collapsing "Vulnerable" and "High Vulnerability" (the two
hardest classes to separate) was the right call regardless of which algorithm is used.

> **Note on small numeric differences:** Random Forest/XGBoost were re-trained from scratch
> in `06_bagging_boosting_models.ipynb` (same hyperparameters, same data, same
> `random_state=42`) so every model in the final comparison comes from one consistent
> environment. That run landed a fraction of a point away from `05_ML_model.ipynb`'s
> original numbers (e.g. RF 4-class: 56.96% here vs. 57.32% originally) -- expected
> library-version drift (scikit-learn/XGBoost versions), not a data or methodology change.
> The tables in the individual `05_*` notebook sections above still show each notebook's own
> original output; the tables here are the ones used for the final cross-model comparison.

## Feature Importance Insights

Feature importance analysis (from the original XGBoost model, see
`outputs/figures/feature_importance.png`) identified the following key predictors:

- Terrain Roughness
- Slope
- Elevation
- Distance to Road
- Rainfall (7-Day)
- Rainfall (15-Day)
- Distance to River
- Building Density

These findings align with established geotechnical and environmental factors known to influence landslide occurrence.

Consistent with this, `07_cnn_image_model.ipynb`'s spatial-patch CNN also carries roughness,
slope, and elevation as 3 of its 12 input channels -- the same variables ranking highest
here. Whether the CNN's neighborhood context helps *most* specifically in high-roughness
terrain (as opposed to across the board) hasn't been tested; it would need a stratified
error analysis by terrain type, which is listed under Future Work rather than claimed here.

## Key Results

Built a complete geospatial feature engineering pipeline

Processed DEM data covering Himachal Pradesh (~163 million pixels)

Generated terrain, rainfall, vegetation, infrastructure, and hydrological features

Constructed a dataset of ~56,000 geospatial samples

Evaluated **10 distinct models across 3 paradigms** -- Bagging (Random Forest, Bagging
Classifier, Extra Trees), Boosting (XGBoost, AdaBoost, Gradient Boosting, LightGBM,
CatBoost), and Deep Learning (MLP on tabular features, CNN on spatially-reconstructed
image patches) -- on both a 4-class and 3-class label scheme (19 total model x scheme
results, all in `outputs/results/model_results.csv`)

Improved performance through risk-category reformulation -- confirmed to help **every**
model, not just the two tested originally

Reconstructed genuine spatial image patches from point data alone (no raw rasters were
available) to train a CNN, verified pixel-exact against the tabular features at each
patch's center

Achieved **68.10% accuracy and 0.670 Macro F1** using a 3-class Random Forest model --
still the top result, though XGBoost achieves comparable accuracy (65.35%) with roughly a
third of Random Forest's overfitting gap, Gradient Boosting achieves the best accuracy/gap
balance outside of Random Forest and XGBoost (60.5% accuracy at only a 2.9-point gap), and
the CNN reaches competitive accuracy (58.51%) from a fundamentally different, spatially-aware
architecture while still avoiding the Bagging family's heavy overfitting

**The full picture, not just the top score:** this project's real conclusion isn't "Random
Forest wins" -- it's that accuracy and generalization pull in different directions across
every algorithm family tested, and which one to deploy depends on whether the priority is
peak accuracy on this test set or robustness to distribution shift. Full reasoning in
`08_final_comparison.ipynb`.
